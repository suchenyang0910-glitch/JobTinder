# JobTinder V0.1 视觉设计规范

版本：2026-09-21  
状态：开发基线  
参考：[KhmerX × PayEase 样式库](https://payease-style.khmerx.org/?release=0c2a188df6c4#chart-catalog)

## 1. 设计原则

JobTinder 借鉴 PayEase 样式库的设计方法，不复制其金融品牌、文案或页面。设计应让用户快速回答三件事：这是什么岗位、为什么推荐、下一步做什么。

1. 信息先于装饰：岗位来源、工作内容、薪酬状态和匹配理由默认可见。
2. 一屏一个主行动：求职者优先“查看岗位/表达兴趣”，企业优先“处理待办/发布岗位”。
3. 状态必须可读：颜色只是辅助，状态同时用文字、图标和布局表达。
4. 每个页面交付完整状态：加载、空态、受限、失败、保存中、成功、会话失效。
5. 视觉语气随角色变化，但 Token、组件行为和可访问性保持一致。
6. 动效帮助理解，不替代事实；客户端动画不代表 Match、联系开放或岗位仍有效。

## 2. 三种 JobTinder 视觉语气

| 语气 | 使用范围 | 视觉特征 |
|---|---|---|
| Calm Match | 求职者 Bot/Mini App、欢迎、建档、岗位卡、Match | 浅蓝灰背景、充足留白、单一主 CTA、卡片阅读优先 |
| Operator Grid | 企业端和运营后台、岗位维护、兴趣待办、来源复核 | 信息密度较高、固定表头、筛选胶囊、队列优先 |
| Trust Surface | 来源证据、岗位状态、匹配理由、联系方式开放、举报审核 | 克制白/深灰表面、事实摘要、来源和时间戳、状态轨迹 |

不使用“Insight Ledger”展示个人推荐分或个人画像评分。若做运营看板，只展示授权的聚合数据，并附统计范围、更新时间和数据状态。

## 3. 设计 Token

### 3.1 颜色

```css
:root {
  --jt-brand: #1677ff;
  --jt-brand-hover: #0f64d8;
  --jt-brand-soft: #eaf3ff;
  --jt-ink: #172033;
  --jt-muted: #667085;
  --jt-subtle: #98a2b3;
  --jt-line: #e4e7ec;
  --jt-surface: #ffffff;
  --jt-canvas: #f6f8fb;
  --jt-success: #00a870;
  --jt-success-soft: #e7f8f2;
  --jt-warning: #f79009;
  --jt-warning-soft: #fff4e5;
  --jt-danger: #d92d20;
  --jt-danger-soft: #feefee;
  --jt-info: #2e90fa;
}
```

颜色规则：

- 蓝色只表示主行动、链接、选中态和可继续；
- 绿色表示已匹配、已开放联系、已确认；
- 橙色表示待补充、待处理、面议或需要用户确认；
- 红色表示失败、举报、明确冲突和关闭；
- `面议`不使用绿色，不表示薪资已满足；用中性文字加橙色辅助标记；
- 不得用颜色作为唯一状态信息，至少同时展示文字或图标。

### 3.2 字体与字阶

优先使用系统字体，支持中文、英文和高棉文：

```css
font-family: Inter, "Noto Sans Khmer", "Noto Sans SC", system-ui, sans-serif;
```

字阶固定为：24 / 18 / 16 / 14 / 12px。

| 用途 | 字号/行高 | 重量 |
|---|---:|---:|
| 页面标题 | 24/32 | 700 |
| 区块标题 | 18/26 | 700 |
| 卡片标题、主按钮 | 16/24 | 600 |
| 正文、输入内容 | 14/22 | 400/500 |
| 说明、来源、合规提示 | 12/18 | 400 |

高棉语可能比中文占用更多宽度，不能用固定宽度截断关键岗位名、薪酬说明和来源。

### 3.3 间距、圆角、尺寸

- 只使用 8pt 网格：8 / 12 / 16 / 24 / 32 / 40px；
- 输入框和主要控件高度 48px；后台密集表格行高 56px；
- 圆角：输入框 8px、按钮/小控件 10px、卡片/抽屉 16px；
- 移动端横向边距 16px，内容最大宽度 640px；后台桌面端最大宽度 1280px；
- 主按钮触控区域不小于 48×48px；危险按钮不与主按钮视觉混淆。

## 4. 页面布局

### 4.1 求职者 Calm Match

首屏结构：

1. 顶部：语言、通知和资料入口；
2. 状态卡：当前求职状态、待补充数量或新 Match；
3. 一张岗位卡：岗位名、企业、地点、工作内容、薪酬状态、来源；
4. 匹配理由：技能、行业、岗位、工作内容关键词；
5. 底部固定操作栏：`查看原文/官网申请` 或 `感兴趣`。

岗位卡不可只显示岗位名称和 Logo。官网采集岗位必须显示“官网采集 · 企业未入驻”和最后核查时间。

### 4.2 企业 Operator Grid

桌面端采用三栏：左侧导航，中间待办/列表，右侧事实摘要和操作。移动端改为单栏，事实摘要先于操作。

- 顶部显示一个首要待办数量；
- 筛选使用可清除的胶囊：待处理、已匹配、已关闭、来源待复核；
- 列表固定表头，状态、岗位、更新时间和下一步动作可见；
- 详情页底部显示只读审计轨迹；
- 不能在列表中直接改写权威岗位条件，必须进入确认流程。

### 4.3 Trust Surface

用于来源、匹配和联系事实：左侧标签/状态，中央事实摘要，右侧来源与时间。关键内容固定可见，不能藏在翻转卡片、手势或只读弹窗后。

事实卡必须区分：

- `官网采集`：来自公开原文，企业未入驻；
- `企业确认`：入驻负责人确认过的岗位；
- `本人确认`：求职者本人确认的技能和意向；
- `未知/未提供`：没有依据，不填补；
- `面议`：官网未公开薪资，不是薪资已满足。

## 5. 组件规范

### 5.1 按钮

- Primary：每个视图最多一个，颜色为 `--jt-brand`；
- Secondary：查看详情、修改、保存草稿；
- Tertiary：跳过、返回、稍后处理；
- Danger：举报、屏蔽、删除，必须有明确文字；
- 禁止用“滑动确认”代替表达兴趣、开放联系方式或删除账号；
- 点击后立即进入 `保存中/处理中`，防止重复提交。

### 5.2 卡片、标签与来源徽标

卡片标题、关键条件和主行动在折叠前可见。标签示例：`技能匹配`、`行业相关`、`官网采集`、`企业未入驻`、`面议`、`待补充`。

来源徽标必须包含来源类型；不使用“已验证”这种超出证据范围的词。可使用“官网来源”“企业确认”“本人确认”。

### 5.3 表单与 AI 草稿

采用分步表单和就近错误：

- 顶部显示当前步骤和剩余关键问题；
- AI 提取字段带“AI 整理”标识；
- 用户修改后标记为“本人确认”；
- 未提供字段显示“未提供/未知”，不显示空白造成误解；
- 保存中显示时间，失败在字段附近说明原因并提供重试；
- 只有影响匹配的字段才追问，不做长问卷。

### 5.4 状态组件

所有列表、岗位卡、Match 和表单必须实现：

| 状态 | 视觉表达 |
|---|---|
| 加载 | 骨架屏，保持布局稳定 |
| 空态 | 说明为什么为空 + 一个主行动 |
| 受限 | 说明权限边界，不泄露对象详情 |
| 失败 | 明确原因 + 重试/人工处理入口 |
| 待处理 | 橙色标签 + 截止时间 |
| 已匹配/联系开放 | 绿色标签 + 联系行动 |
| 已关闭/失效 | 灰色或红色文字 + 失效原因 |

## 6. 动效与手势

- 页面转场 180–240ms，使用 ease-out；
- 卡片进入可使用轻微淡入/上移，不能造成岗位内容跳动；
- 低风险筛选、折叠、Tab 和列表排序可使用 Motion；
- 减少动态效果模式下关闭弹簧、视差、自动滚动和连续动画；
- “感兴趣”使用按钮，不做约会软件式快速滑卡作为唯一入口；
- 官网申请、联系方式开放和 Match 以服务端状态为准，动效只是反馈。

## 7. 图表与运营看板

仅用于聚合运营数据，例如岗位来源数量、待处理兴趣数、处理时长分布。每张图必须带标题、单位、时间范围、更新时间、数值摘要和数据状态（待核验/已确认）。

禁止展示个人匹配分、个人风险分、内部拒绝规则或未经确认的招聘结果。推荐解释优先用可读标签和字段证据，不用圆环图伪造“适合度”。

## 8. 三语与可访问性

- 首版文案结构支持 `zh-CN`、`en`、`km`；
- 任何文本不得写死在组件中，统一使用翻译键；
- 支持键盘焦点、屏幕阅读器标签、Esc 关闭、Enter 提交；
- 对比度按 WCAG AA 目标；
- 颜色、图标、文字三者至少两种同时表达状态；
- 触控区域不小于 48px；
- 用户可以不用手势完成所有关键动作。

## 9. 视觉验收

交付每个页面时，Trae 必须提供浅色和深色、320px 移动宽度、桌面宽度、中文/英文/高棉文，以及加载、空、失败、受限和成功状态。截图或预览必须能看到来源、薪酬状态、匹配理由和唯一主行动。

视觉参考站中可复用的是 Token、状态交付、信息层级和受控动效方法；JobTinder 的岗位来源、免费服务、24/72 小时规则和联系方式逻辑以本项目文档为准。
